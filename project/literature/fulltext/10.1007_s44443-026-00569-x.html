Abstract

Code vulnerabilities pose a critical security threat, with potential consequences such as data breaches in e-government systems, risking societal stability and national security. While deep learning (DL)-based methods have advanced vulnerability detection by leveraging graph neural networks (GNNs), existing approaches often neglect local semantic details and underutilize diverse edge types in code structure graphs. To address these limitations, this study aims to develop a comprehensive vulnerability detection framework that integrates both local and global semantic information. We propose MDFVD (Multi-Dimensional-Feature-based Vulnerability Detection), which introduces two key innovations: a Multi-dimensional node Feature extraction strategy (MFES) combined with Attention-based Bidirectional Gated Recurrent Unit (ABiGRU) to capture fine-grained local semantic features, and an Attention Mechanism and Multi-layer Feature Fusion-based Relational GCN (AMF-RGCN) to model diverse edge relationships for enhanced global structural learning. Additionally, we design a novel Combination Code Property Graph (ComCPG) that enriches syntactic and contextual information to better represent source code structure. Extensive experiments on four benchmark datasets validate MDFVD’s effectiveness. Compared to state-of-the-art baselines, MDFVD achieves F1-score improvements of 15.15%, 21.25%, 9.37% and 14.67% across datasets. These results demonstrate that integrating MFES for local semantics and AMF-RGCN for structural edge utilization, alongside ComCPG, enables more robust vulnerability detection.

1 Introduction

As the scale and complexity of software development continue to expand, software security matters have grown more and more serious, and flaws in source code have turned into a major obstacle within the realm of information security. These flaws may trigger serious outcomes like system assaults, data leaks, and service disruptions, thereby inflicting considerable economic losses on both enterprises and individuals. In the field of e-government, for instance, once there are vulnerabilities in the code, which may lead to severe consequences such as data leakage, it will pose a potential risk to social stability and national security. In order to deal with the rising prevalence and elusive quality of software security.

In recent years, deep learning has shown remarkable capabilities in vulnerability mining and code feature extraction (Menzies et al. 2006; Chakraborty et al. 2021), which has spurred the development of deep learning-based vulnerability detection. Through the utilization of deep learning algorithms to train detection models, these approaches can uncover complex and hidden connections between vulnerabilities and code features within high-dimensional data, thus facilitating precise risk prediction. Typical deep learning-based methodologies usually present source code in the form of sequential data and subsequently employ natural language processing (NLP) techniques to extract features. As an illustration, the VulDeePecker (Li et al. 2018) model utilizes code slicing to handle risky function calls and vectorizes the slices for vulnerability detection purposes. Other techniques (Medeiros et al. 2014; Li et al. 2017; Feng et al. 2020a) represent source code as tree structures like abstract syntax trees (ASTs), where nodes signify code elements and edges denote syntactic relationships. Nevertheless, NLP-based methods frequently struggle to capture the essential structural characteristics of programs, rendering them insufficient for intricate vulnerability patterns.

Recent advances in software vulnerability detection have increasingly adopted graph-based representations to address the structural complexity of source code analysis. Unlike traditional text-processing approaches, graph models systematically organize code components into nodes (e.g., functions, variables) and edges that explicitly encode semantic relationships like control flows, data dependencies, and function interactions (Feng et al. 2020b). This structured representation preserves both syntactic details and contextual program logic that linear text formats often obscure, particularly benefiting the detection of inter-procedural vulnerabilities (Wi et al. 2022).

The flexibility of graph structures enables a thorough modeling of code semantics by integrating ASTs, Control Flow Graphs (CFG), and Data Dependency Graphs (DDG) (Ghaffarian and Shahriari 2021; Song et al. 2022). Recent innovations like Code Property Graphs (Wi et al. 2022) and heterogeneous intermediate representations (Song et al. 2022) further enhance this paradigm by integrating multiple code perspectives. Empirical studies demonstrate that graph neural networks (GNNs) processing such representations achieve superior accuracy in detecting cross-procedural flaws-DeepWukong (Cheng et al. 2021) demonstrates performance advantages over sequence models for memory leak detection.

However, current methodologies still face critical limitations: Existing graph constructions often inadequately encode contextual program structures, leading to suboptimal feature capture capabilities. The modeling of long-range dependencies between code elements remains challenging due to inherent graph sparsity and connectivity patterns. Furthermore, processing complex multi-dimensional graph structures continues to encounter efficiency bottlenecks during vulnerability pattern extraction. These persistent challenges underscore the need for enhanced graph representation learning strategies in vulnerability detection research.

The VulSniper (Duan et al. 2019) system achieves fine-grained vulnerability detection through code property graphs, but its graph construction is based on a conventional CPG that lacks explicit edges for inter-procedural relationships. It does not fully integrate contextual information about function call chains, making it difficult to capture semantic patterns that depend on cross-function interactions; meanwhile, the code property graph has limited representation ability for the natural lexical order of statements, which can provide complementary structural cues.

The FUNDED framework (Wang et al. 2020) realizes flow-sensitive detection through graph structure learning, but its core graph representation is also derived from static code analysis and focuses primarily on intra-procedural control and data flow. It lacks explicit modeling of function call relationships as first-class edges in the graph, limiting its ability to capture vulnerability patterns that propagate across function boundaries; in addition, when dealing with large-scale codebases, the sparsity of the graph structure and the absence of lexical-order connections can lead to fragmented representations that hinder learning.

Zhou’s Devign (2019) model constructs graph structures by integrating code information to understand program semantics, but its graph construction relies on historical code commit data, and the unbalanced distribution of vulnerability types in training samples results in insufficient generalization ability of the model for new vulnerabilities; at the same time, the model does not distinguish the priority of control flow and data flow, which easily loses key path information in complex conditional branches, especially with low positioning accuracy for logical vulnerabilities.

LineVD (Hin et al. 2022) uses single instructions as graph nodes to achieve statement-level detection, but the overly fine-grained nodes lead to a surge in graph scale, increasing computational complexity and memory consumption; moreover, this method focuses on intra-function statement relationships, ignoring the high-level semantics of inter-function call chains, making it difficult to identify vulnerabilities transmitted across functions; in addition, static graph construction does not incorporate variable lifecycle information, resulting in limited detection effectiveness for timing-dependent vulnerabilities such as memory leaks.

Cao ’s MVD model (2022) improves detection comprehensiveness through static/dynamic hybrid graphs, but its dynamic information relies on program execution traces, lacking effective modeling for uncovered abnormal execution paths or boundary conditions; hybrid graph construction needs to combine dynamic execution data, leading to increased complexity of the detection process, and the model does not fully handle semantic conflicts when fusing static structure and dynamic flow information, which may introduce noise and affect the detection accuracy of complex memory vulnerabilities.

However, current methodologies still face critical limitations in static graph representation: Existing graph constructions often inadequately encode inter-procedural call relationships and the natural lexical structure of code, leading to suboptimal feature capture capabilities. The modeling of long-range dependencies between code elements remains challenging due to inherent graph sparsity and the lack of edges that capture consistent, execution-path-agnostic code layout. These persistent challenges underscore the need for enhanced static graph representation learning strategies that incorporate a more comprehensive set of code relationships.

In this paper, we propose a novel vulnerability detection model, named MDFVD (Multi-Dimensional-Feature-based Vulnerability Detection). This model takes into account both the local and global syntactic and semantic information of the code, enabling a more comprehensive extraction of vulnerability features. MDFVD primarily consists of two components.

In terms of local node feature extraction, MDFVD presents a method that combines a Multi-dimensional node Feature extraction strategy (MFES) with the Bidirectional Gated Recurrent Unit with Attention Mechanism (ABiGRU). MFES and ABiGRU can extract the local syntactic attributes and semantic features embedded in each statement from the Subtree of AST (Sub-AST), Program Dependence Graph Context (PDG-Context), and Combination Code Property Graph (ComCPG), and convert them into corresponding vector representations. These vector representations serve as the local semantic information within the code statements.

In addition, MDFVD also proposes an improvement strategy of GCN Based on Attention Mechanism and Multi-layer Feature Fusion (AMF-RGCN). Through AMF-RGCN, MDFVD can capture the global feature information of the entire code segment, thereby more thoroughly extracting vulnerability features and enhancing the final ability to identify vulnerabilities.

Notably, ComCPG is a novel graph-based code representation proposed in this study, incorporating function call relationships and natural control flow edges into traditional code property graphs to strengthen semantic and contextual information representation.

By utilizing the datasets from ReVeal (Chakraborty et al. 2021), (Fan et al. 2020), FFmpeg+QEMU (Zhou et al. 2019) and SARD (2024), this research systematically examines the vulnerability detection capability of MDFVD. The experimental outcomes indicate that MDFVD surpasses the conventional methods in detection accuracy. The primary achievements of this research are listed below:

  • A new vulnerability detection model, MDFVD, is proposed to simultaneously take into account the local and global semantic information of the code. It combines MFES with ABiGRU for local node feature extraction and introduces AMF-RGCN to capture global code segment features via relational edge updates.

  • A novel graph representation, ComCPG, is presented for extracting semantic features from source code. Compared to traditional CPG, it integrates Function Call Graph (FCG) and Natural Control Sequence (NCS) edges to enhance structural and contextual coherence.

  • A series of innovative experiments were designed to systematically validate the effectiveness and advantages of the MDFVD method, including comparisons with five baselines on four datasets, ablation studies, and vulnerability type evaluations. MDFVD achieves F1-score improvements of 15.15%, 21.25%, 9.37% and 14.67% over the best baselines on each dataset.

The remainder of this paper is organized as follows. Section 2 presents an overview of fundamental technologies. Section 3 surveys related research. Section 4 describes the components of MDFVD. Section 5 details the datasets and experimental setup. Section 6 reports the experimental outcomes and evaluations. Section 7 analyzes the effectiveness and limitations of MDFVD. Section 8 concludes the paper.

2.3 Relevant technologies

This section introduces the background of relevant technologies.

2.3.1 Abstract syntax tree

Programs are written following specific syntax rules, and their structural features can be represented using ASTs. An AST represents the abstract syntax structure of a program in a tree form, where nodes contain lexical information, and subtrees formed by nodes and edges represent code blocks. ASTs are widely used for analyzing program structures. Extracting structural features from ASTs using deep learning models and utilizing them for downstream tasks–such as code completion (Wang and Li 2021), code summarization (Tang et al. 2022), vulnerability detection (Zhuang et al. 2021), and defect prediction (Liang et al. 2019)–has recently attracted significant research attention in software engineering.

2.3.2 Program dependence graph

A PDG is a graphical depiction of source code derived from control-flow and data-flow analysis. It encompasses both data dependencies and control dependencies. Control dependencies represent execution relationships between program statements, often associated with logical control structures (e.g., if-else, for, while, switch-case). Data dependencies indicate the relationships between variable definitions and uses. Nodes in a PDG represent code statements, while edges denote dependencies. PDGs provide a foundation for program analysis and are widely used in program understanding (Ferrante et al. 1987).

2.3.3 Contextual information

Contextual information is derived from statement nodes in a PDG. For a given statement node V, its context is defined as the set of all statement nodes connected to V within the PDG. This information encompasses all data and control dependencies of V. Contextual information enriches the local semantics of statement nodes and provides comprehensive semantic clues for model learning, aiding in the efficient capture of global semantic features and improving the performance of downstream tasks.

2.3.4 CPG

CPG is a foundational graph-based code representation that integrates multiple single-purpose program analysis graphs into a unified data structure. It was originally proposed to facilitate efficient vulnerability pattern matching. A CPG merges AST, CFG, and PDG by superimposing their nodes and unions of their edges.

Formal definition

A CPG for a function or code fragment is defined as a directed graph \(G_{\text {CPG}} = (V, E_{\text {CPG}})\). V is the set of nodes, each representing a distinct syntactic element (e.g., statement, expression, variable) from the source code. The node set is the union of the nodes from the constituent AST, CFG, and PDG representations. \(E_CPG\) is the set of directed edges, which is the union of edges from the constituent graphs.

$$\begin{aligned} E_{\text {CPG}} = E_{\text {AST}} \cup E_{\text {CFG}} \cup E_{\text {PDG}} \end{aligned}$$

Here, \(E_AST\) represents parent-child syntactic relationships, \(E_CFG\) represents possible execution sequences between basic blocks, and \(E_PDG\) includes both data dependence (\(E_DDG\)) and control dependence (\(E_CDG\)) edges.

Key characteristics and role

The CPG’s primary strength lies in its ability to encode syntactic, control-flow, and data-flow information simultaneously within a single graph. This allows an analysis to reason about a program’s structure (via AST edges), its possible execution paths (via CFG edges), and the relationships between definitions and uses of variables (via PDG edges) without switching between different representations. It serves as a powerful graph-based code representation for static analysis tasks, including vulnerability detection, as it makes complex code properties explicit and machine-learnable.

The CPG forms the core structural backbone of our proposed ComCPG, which extends it with additional semantic edges, as defined in the next section.

2.3.5 ComCPG

Traditional CPGs cannot represent inter-function call relationships. To address this limitation, ComCPG extends the original CPG by incorporating FCG and NCS as edges, creating a more expressive graph structure. ComCPG consists of nodes representing syntactic units and directed edges representing relationships between nodes. The detailed definition of ComCPG is provided below.

Formal definition of NCS edges

Within a ComCPG \(CG = (V, E)\), an NCS edge is a directed edge \(e_{ncs} = (v_i, v_j) \in E\) that represents a natural lexical succession relationship between two statement nodes \(v_i, v_j \in V\). This relationship is defined independently of explicit control flow and aims to capture the order in which statements would be naturally encountered in a depth-first traversal of the abstract syntax, before control flow divergence. For a statement node \(v_i\), its natural successor \(v_j\) is determined as follows:

$$\begin{aligned} v_j = {\left\{ \begin{array}{ll} \text {lex\_first}(v_i.\text {true\_branch}), & \text {if } v_i \text { is a conditional (e.g., `if`) and has a true branch}\\ \text {lex\_first}(v_i.\text {false\_branch}), & \text {if } v_i \text { is a conditional with a false branch and no true branch}\\ \text {lex\_succ}(v_i), & \text {otherwise (sequential flow)} \end{array}\right. } \end{aligned}$$
(1)

where \(\text {lex\_first}(branch)\) returns the lexically first statement node within a given code block, and \(\text {lex\_succ}(v_i)\) returns the immediate lexical successor of \(v_i\) within the same basic block.

To address the potential scalability challenge of ComCPG generation in large-scale codebases, we propose a two-stage optimization strategy: a Layered Incremental Update Algorithm and an Edge Pruning Strategy.

Layered incremental update algorithm

The algorithm constructs ComCPG hierarchically (Project \(\rightarrow \) Module \(\rightarrow \) Function) and updates it incrementally based on code changes, avoiding full-graph reconstruction. It leverages version control metadata (e.g., Git diff) to identify modified modules and only regenerates the corresponding subgraphs and their inter-module FCG edges.

Time complexity analysis

Let M be the total number of modules, \(N_m\) the average nodes per module, and k the number of modules affected by a change. The worst-case time complexity of the original generation is \(O(N^2)\). With incremental update, the complexity reduces to \(O(k \cdot N_m \log N_m + E_{inter})\), where \(E_{inter}\) is the number of inter-module edges. For localized changes (\(k \ll M\)), this approximates \(O(N \log N)\).

Edge pruning strategy

To further reduce graph size, we prune edges that have low correlation with historical vulnerabilities. We define a Vulnerability Correlation Score (VCS) for each edge type t based on its conditional probability in vulnerable functions within the training set:

$$\begin{aligned} VCS(t) = P(\text {Vulnerable} \mid \text {Edge type } t \text { present}). \end{aligned}$$
(2)

Edges with VCS below a threshold \(\tau \) (determined by maximizing information gain on the training set) are pruned. Typically, NCS edges within basic blocks and certain AST edges are pruned.

Technical rationale and integration challenges

While the individual concepts of function calls (FCG) and lexical order (NCS) are not new, their seamless and semantically coherent integration into a unified CPG framework presents distinct technical challenges that prior work often circumvented. FCG edges operate at the inter-procedural level between function entry points, while NCS, AST, CFG, and PDG edges are intra-procedural. Merging these scales into a single, ComCPG requires resolving node identity and granularity mismatches. We address this by unifying all representations at the statement-level granularity and introducing explicit connector nodes for function entries, ensuring a consistent graph schema for neural processing. Simply taking the union of edges from different graphs can create redundancy (e.g., an AST edge and an NCS edge between the same nodes) or even semantic conflicts (e.g., a CFG edge suggesting one execution order and an NCS edge suggesting another). The novelty of ComCPG lies in its principled edge co-existence model. We define NCS not as an alternative to CFG but as a complementary relation capturing lexical layout, which provides a stable, context-rich connective tissue that is invariant to specific execution paths. This complementary design, where edge types encode different semantic axes (syntax, execution, dependence, calls, and lexical order), is what enables more comprehensive feature extraction. Uncontrolled addition of edges can lead to overly dense or noisy graphs, hindering the learning process of GNNs. Our integration is coupled with the AMF-RGCN model (Section 4.2), which is specifically designed to leverage this multi-relational structure through relation-specific weight matrices and attention-based fusion, effectively distilling useful signals from the enriched graph.

Previous graph-based vulnerability detection models (e.g., Devign, Reveal) primarily extended the CPG by deepening feature learning on its original edge set (AST, CFG, PDG) or by incorporating external sequence information. The explicit incorporation of structured inter-procedural context (FCG) and invariant lexical flow (NCS) as first-class edge types within the CPG, along with a neural architecture designed to exploit them, is the key novelty of ComCPG. It addresses the long-standing limitations of CPGs in modeling cross-function interactions and leveraging the consistent structural cues present in source code layout.

3 Related work

Our work incorporates a variety of advanced techniques from the domains of GNNs, NLP, and DL. In this section, we will explore the relevant research in these fields.

3.1 Conventional machine-learning-based vulnerability detection methods

In the era of the upsurge of traditional machine learning, a multitude of studies employed these techniques for vulnerability detection. For example, Yamaguchi et al. (2013) put forward a system called Chucky for detecting vulnerabilities. Chucky combines machine learning with static program analysis to precisely identify vulnerabilities, employing k-nearest neighbor and bag-of-words techniques. However, it was only capable of detecting two types of vulnerabilities, and the false-positive rate was relatively high. Shar et al. (2014) presented a vulnerability prediction tool that used hybrid program analysis and machine learning to detect SQLI and XSS vulnerabilities in PHP web applications. In their research, they tested two classification models, namely MLP and Logistic regression. Nevertheless, they only carried out tests on small-scale datasets and lacked large-scale experiments.

3.2 Deep-learning-based vulnerability detection approaches

With advancements in deep learning, increasing research efforts are applying deep-learning techniques to vulnerability detection. Li et al. (2018) developed a method utilizing code gadgets extracted from data dependencies and employing Bidirectional Long Short-Term Memory for vulnerability identification. However, this approach was restricted to detecting vulnerabilities related to library or API function calls. Russell et al. proposed a deep-learning-based vulnerability detection framework adopting feature extraction strategies analogous to sentence sentiment classification. Specifically, they performed lexical analysis and normalization on source code, generated embedding representations, followed by function-level source code vulnerability classification using Convolutional Neural Networks (CNNs) and Recurrent Neural Networks (RNNs), subsequently employing random forests for vulnerability detection (Russell et al. 2018).

3.3 Graph neural network

Recent years have witnessed extensive efforts to leverage neural networks for graph-structured data, such as transportation networks (Bui et al. 2022), and conduct analyses on such data using GNNs. GNNs have further been adopted across diverse NLP applications. For example, Yao et al. (2019) applied GNNs to model word co-occurrences and document-word relationships for text classification. Researchers have also utilized GNNs to encode source code for addressing various software engineering tasks, including code summarization (Leclair et al. 2020).

3.4 GNN-based software vulnerability detection

Recent progress shows that general GNNs and their variants are extremely effective in function-level vulnerability detection. For example, DeepWukong, proposed by Cheng et al. (2021), extracts program slices based on the PDG and inputs these slices into a GCN for vulnerability detection. Zhou et al. (2019) proposed the Devign model, employing a general graph neural network for vulnerability detection. This framework integrates a novel convolutional module that efficiently extracts salient features from learned rich node representations to facilitate graph-level classification. Chakraborty et al. (2021) presented a GNN-based model called REVEAL for function-level vulnerability detection. REVEAL transforms real-world code into graphs and then uses representation learning techniques to build a model, allowing the model to automatically learn the features representing vulnerable and benign code in the feature space. Wang et al. (2020) proposed a GGNN-based model named FUNDED. This model works on the graph representation of input functions and can learn and aggregate various code relationships, such as data, control, operation sequence, and operation values. IVDETECT, proposed by Li et al. (2021), is also a GNN-based function-level vulnerability detection model. It represents functions using PDG and then feeds the PDG into a GNN for classification to determine if a function has vulnerabilities. Li et al. (2017) proposed a document-level DP-CNN model that constructs vectors from ASTs, learns features through neural networks, and classifies results using logistic regression. Similarly, Lin et al. (2018) converted function code into ASTs, represented them as sequential language tokens through depth-first search (DFS), and applied Word2Vec embeddings followed by Bi-LSTM for feature extraction. Guanjun et al. introduced POSTER (Lin et al. 2017), a function-level vulnerability detection method that uses AST representations and bidirectional LSTM (BLSTM) networks. Zhen et al. developed VulDeeLocator (Li et al. 2021), the first deep-learning-based source-code vulnerability detector that achieves high-precision localization by integrating granular refinement and bidirectional recurrent neural networks. Duan et al. proposed VulSniper (Duan et al. 2019), which employs attention mechanisms to compute node weights for identifying critical code segments, followed by fully connected layers for binary classification. VulCNN (Wu et al. 2022) converts function-level PDGs into social network analogs, integrates centrality metrics (degree, Katz, closeness), and uses CNNs for detection. mVulPreter (Zou et al. 2022) combines slice-level granularity with function-level semantics through a novel interpreter. Zou et al. developed \(\mu \)VulDeePecker (Zou et al. 2019), a multi-class detection system focusing on API-related vulnerabilities in C/C++ using Bi-LSTM and attention. Li et al. enhanced VulDeePecker with SySeVR (Li et al. 2021), introducing syntactic/semantic vulnerability candidates and array/pointer-based slicing via Bi-GRU. Xu et al. (2018) combined program slicing, code normalization, and hybrid CNN-RNN architectures to leverage local/contextual features.

4 MDFVD method

This research centers on boosting the semantic feature extraction ability of source code and enhancing the comprehensiveness and accuracy of vulnerability detection. The overall framework is shown in Fig. 3.

MDFVD is primarily composed of two components, designed to operate at different granularities for function-level vulnerability detection. First, MFES is used to extract the fine-grained syntactic attributes and semantic features contained in each individual statement of the code representation, converting them into vector representations. These serve as local node-level semantic information. Then, AMF-RGCN is employed to propagate and aggregate these node features across the entire graph representation of the input function. This process captures the global, intra-procedural semantic information–the complex interplay of statements, control flows, and data dependencies throughout the function–enabling a holistic, function-level classification.

4.1 MFES: a multi-dimensional node feature fusion and extraction strategy

In the research process of deep learning-based vulnerability detection methods, it is first necessary to parse the source code in the dataset, selectively preserve code semantic information, and generate appropriate graph-based code representations to facilitate subsequent extraction of code feature information for identifying potential vulnerabilities in software. However, the code representation methods proposed in current vulnerability detection approaches still suffer from issues such as incomplete semantic information in code representation, excessive redundant information, and high complexity. Therefore, to address the above issues, this section proposes a source code representation extraction strategy based on multi-dimensional node feature fusion, named MFES. This strategy combines multi-dimensional code representations such as line-level Sub-AST, line-level PDG-Context, and ComCPG to form a multi-dimensional semantic graph.

Specifically, it first extracts the ComCPG of the function source code as the basic graph structure, then extracts the Sub-AST and PDG-Context of each ComCPG statement node as supplementary information for ComCPG nodes, representing structural and syntactic information, data dependencies, and control dependencies within the statement nodes. Finally, the GloVe model is used to implement node information embedding. This multi-dimensional semantic graph, generated with statement-level nodes as the fusion point, can integrate multiple dimensions of code representation forms and their represented semantic information. While minimizing redundant information and reducing complexity, it maximizes the representation of various semantic information, providing an abstract representation graph that fully reflects effective information such as code syntax and semantics for subsequent feature extraction and representation learning in vulnerability detection research.

4.1.1 Construction of Multi-Dimensional Semantic Graph (MDSG)

The construction process of the multi-dimensional semantic graph is shown in Fig. 4.

This chapter uses the open-source static code analysis tool Joern to analyze and process the function samples in the dataset, generate corresponding ASTs, PDGs, and CPGs, and generate the corresponding ComCPG according to the method described below. The main reason for using this tool is that it can directly perform code parsing and automatically generate different code representations without going through the pre-compilation stage, thereby significantly reducing the complexity of user operations and the cost invested. It should be noted that the input of the strategy is a preprocessed dataset in units of functions.

(1) Feature Extraction of Sub-ASTs for Code Lines

The extraction of Sub-AST features is achieved through a combination of the static analysis tool Joern and Python scripts. First, Joern is used to obtain a global subgraph of the code and extract the corresponding AST substructure for each code line. Next, by combining the tokens of the code line with character matching, the last node information of the previous sub-tree is added to the current line’s abstract syntax tree substructure. This results in the final Sub-AST, from which features are extracted. The detailed process is shown in Figure 5.

Compared to directly extracting the AST of a code line, the Sub-AST, generated based on the global abstract syntax tree and character matching, more effectively preserves the global context of the code. After extracting the Sub-AST, this study uses a Multi-way Tree-LSTM to convert the Sub-AST into a feature vector, which serves as one of the input features, denoted as \(p_{i1}\).

(2) Extraction of PDG-Context Representation and Vectorization for Code Lines

The extraction of PDG context primarily captures dependency relationships within the code. The process is similar to AST extraction. First, the static analysis tool Joern is used to generate a CPG, from which the PDG is constructed. Next, the PDG is utilized to extract the Data Dependency Context (DDC) and Control Dependency Context (CDC) for each code line. Finally, the extracted context is vectorized using the GloVe word embedding technique, combined with a pre-trained model. The detailed process is illustrated in Fig. 6.

Following the generation of the PDG for the code, a Python script is deployed. This script employs Joern’s API to extract the PDG-Context representation per code line, integrating data flow edges, control flow edges within the PDG, and the Tokens information of corresponding code lines. After getting the DDC and CDC of the code lines, GloVe is applied to convert them into vectors. Consequently, the feature vector of the PDG-Context is acquired, represented as \(p_{i2}\).

During the process of using GloVe for vectorization, due to the varying sizes of program dependency information code blocks in each line, the lengths of the obtained input representations will differ. Therefore, zero-padding technique is employed to obtain fixed-length inputs. To mitigate the impact of padding, a masking layer is added to dynamically instruct the model to ignore the information in the padded parts.

The zero-padding technique involves appending zero-valued elements to the end of the input sequence, ensuring that all input sequences have the same length. While this approach can address the issue of different-length inputs, it may introduce some redundant information, potentially affecting the model’s performance. The masking layer, a special type of layer, can mark the padded parts in the input sequence as invalid, enabling the model to disregard the influence of these parts during computation. As a result, the model can focus on the effective parts for calculation. In this paper, the combination of zero-padding technique and the masking layer enhances the efficiency and accuracy of the model.

(3) Feature Representation and Vectorization of ComCPG

ComCPG is represented as a directed graph \(CG = (Vertex(CG), {Edge}(CG))\). The node set Vertex(CG) encompasses all the nodes of ComCPG, while the edge set Edge(CG) consists of all the directed edges in ComCPG, which are formed by ordered pairs of nodes from Vertex(CG). These directed edges are established based on the dependency relationships in the source code, such as program dependencies and function calls. In this manner, ComCPG can be employed to depict the structure and dependency relationships within the source code, offering valuable information for code analysis tasks.

In code analysis and defect detection, converting source code into machine-learning-compatible formats is fundamental. ComCPG serves as a graph-based source code representation that integrates code structure, syntax, and semantics into a directed acyclic graph (DAG). This DAG captures code elements and their interrelationships. However, ComCPG nodes typically contain string-formatted content, posing challenges for direct machine-learning model processing. Therefore, it is essential to vectorize the node content, that is, represent each node as a numerical vector for subsequent use in deep-learning models.

For the code text of each node in ComCPG, this paper utilizes the Doc2Vec tool to convert it into an initial vector. A corpus containing information about all nodes is constructed, where each node is represented as a set \(to(w_{1}, w_{2}, \ldots , w_{N})\). During model training, when predicting the target \(to(w_{i})\), k tokens before and after it, namely \(w_{i-k}, \ldots , w_{i + k}\), are analyzed to capture the contextual semantic relationships. In the training process, by maximizing the average correct probability of tokens, tokens with similar semantics are made closer in the vector space. The model learns which tokens are more likely to appear within the same window by comparing the target token with negative-sample tokens, thereby obtaining the vector representation of each token and making tokens with similar semantics more aggregated. The vector representation after training can effectively capture the semantic similarity between nodes.

For example, when converting the statement “double func1(double var1, double var2)” into a statement vector, the Doc2Vec model divides the statement into words such as “double”, “func1”, “(”, “var1”, “var2”, “)”. After obtaining the corresponding word vectors, they are concatenated in order to form the statement vector.

After vectorizing each node, the feature matrix FM of ComCPG can be generated by the following formula:

$$\begin{aligned} FM=[Doc2Vec(v_{i})],i=1,2,...,n \end{aligned}$$
(3)

Information transfer between nodes can be achieved by concatenating the feature vector of a node with those of its neighboring nodes. The process of message passing and neighborhood aggregation is shown in Fig. 7.

Specifically, for each node i, its information transfer message is:

$$\begin{aligned} mess_{i}=\sum \frac{1}{\sqrt{dg(i)dg(j)} } (f_{i},f_{j}) \end{aligned}$$
(4)

Here, Nb(i) denotes the set of all neighboring nodes of node i. dg(i) and dg(j) represent the degrees of nodes i and j respectively, while \(f_i\) and \(f_j\) correspond to their feature vectors. For each node i, the message passing from its neighbors is combined through the following aggregation:

$$\begin{aligned} \alpha _{i}=\mu (\sum _{j\in Nb(i)}^{} mess_{i,j}W)mess_{i,j} \end{aligned}$$
(5)

This formulation describes the message passing between nodes i and j, where W denotes the trainable weight matrix and \(\mu (\cdot )\) corresponds to the nonlinear activation function. The updated node feature vector \(p_{i3}\) is subsequently derived by combining the node’s intrinsic feature vector \(f_{i}\) with the aggregated neighbor information \(\alpha _{i}\).

$$\begin{aligned} p_{i3} =[f_{i},\alpha _{i}] \end{aligned}$$
(6)

Through iterative message passing and neighborhood aggregation, node feature vectors are dynamically updated.

(4) Generate MDSG

The three obtained intermediate code representation structures are fused using statement-level nodes as the fusion point to generate a new code representation graph structure. Each statement node contains three different dimensions of code semantic information: Sub-AST, PDG-Context, and ComCPG. Assuming the statement node is a, as shown in the multi-dimensional semantic graph generation section of Fig. 8, a includes three attributes \(pa_1\), \(pa_2\), and \(pa_3\), where: \(pa_1\) represents the grammatical structure information of the code statement; \(pa_2\) represents the control relationship context information of the code statement; and \(pa_3\) represents information such as function calls of the code statement. In this way, the multi-dimensional semantic graph characterizes the key semantic features of the code from different dimensions through three distinct node attributes.

Since the code representation format adopted in this paper is a graph structure based on ComCPG, which is not suitable for direct use as input to neural network models, it is necessary to vectorize the node information of the graph. The obtained vectors are also referred to as the initial feature vectors of the nodes. The GloVe model is used to perform embedding representation on the node information obtained above. First, collect all ComCPG node information corresponding to the source code in the dataset, treat the code lines or blocks in each node as a sentence, decompose the sentence into a token list, and combine them into a vulnerable source code word corpus. Then, train the GloVe model using the corpus to obtain a pre-trained model, and use the pre-trained model to perform vector embedding on the abstract syntax tree subtree node information, control relationship context information, and function call relationship information of all nodes, resulting in three initial features \(fi_1\), \(fi_2\), and \(fi_3\). In this way, the GloVe model can convert the corpus into a vector dictionary, based on which any dimension information of MDSG nodes can be mapped to a dense vector. The calculation process of the node initial feature matrix \(F_v\) of the multi-dimensional semantic graph is shown in (7) to (9).

$$\begin{aligned} f_{ir} = [GloVe(p_{ir} )] , r = 1,2,3 \end{aligned}$$
(7)
$$\begin{aligned} F_{vi} = [f_{i1},f_{i2},f_{i3}] ,i=1,2,\cdots ,n \end{aligned}$$
(8)
$$\begin{aligned} F_{v} =[F_{v1},F_{v2},\cdots ,F_{vn}] \end{aligned}$$
(9)

Where \(p_{ij}\) is the attribute information of a certain dimension of node \(v_i\), \(f_{ij}\) is the initial feature vector obtained by mapping \(p_{ij}\) through GloVe, \(F_{vi}\) is the initial feature matrix of node \(v_i\), and n is the number of nodes.

Rationale for embedding model selection

In the design of MDFVD, we intentionally selected GloVe and Doc2Vec for the initial node feature embedding, rather than more recent Transformer-based pre-trained models such as CodeBERT or UniXcoder. This choice was motivated by several key considerations specific to our multi-graph feature extraction pipeline:

  1. 1.

    Computational Efficiency and Stability: GloVe and Doc2Vec are lightweight, static embedding models. Generating embeddings for tens of thousands of code statements and graph nodes during the graph construction phase is computationally inexpensive and deterministic. In contrast, generating contextualized embeddings on-the-fly for each node using a large Transformer model would introduce significant overhead and complexity to the preprocessing stage, becoming a bottleneck for large-scale datasets.

  2. 2.

    Specialization for Local Code Context: Our MFES strategy extracts local semantic features from isolated code elements (e.g., a single statement’s Sub-AST, a node’s immediate PDG context, a function call signature). For these localized, often short text sequences, the global context modeling power of Transformers offers diminishing returns. GloVe and Doc2Vec, trained directly on our corpus of code tokens and statements, efficiently capture the local lexical and syntactic patterns relevant to these granular units.

  3. 3.

    Integration with Subsequent GNN Architecture: The primary role of these initial embeddings is to provide a dense, fixed-dimensional starting point for the subsequent specialized neural networks (Tree-LSTM, GRU) within MNEN and the graph convolutions in AMF-RGCN. These downstream networks are responsible for learning higher-order, structural, and global semantic relationships. A simpler, static embedding proved to be a stable and effective foundation for this learning process, allowing the GNN to focus on structural propagation rather than reinterpretation of complex, pre-computed contextual embeddings.

We acknowledge that Transformer-based models excel at capturing deep semantic relationships in longer code sequences. Our design choice reflects a trade-off, prioritizing a streamlined, efficient, and stable feature extraction pipeline tailored to our graph-based learning objective, where the graph structure itself becomes the primary vehicle for modeling complex, non-local code relationships.

4.1.2 MNEN: multi-dimensional node feature extraction network

Since MDSG integrates multiple code representation forms, common neural network algorithms may encounter issues such as incomplete feature extraction when directly used as node feature extraction methods. In vulnerability detection, the quality of feature extraction directly affects the accuracy of the detection model. To extract the feature information contained in graph nodes as completely as possible, and inspired by the feature pyramid in the field of image processing (Lin et al. 2017), MFES designs MNEN for vulnerability feature extraction. MNEN adopts a three-layer structure to extract features corresponding to three different dimensions of initial node features respectively. In addition, feature vectors of different dimensions are concatenated through feature fusion technology to improve the detection model’s perception ability of vulnerability features and enhance the performance of the detection model. The overall network structure is shown in Fig. 8. The position and role of MNEN within the overall MDFVD framework are illustrated in Fig. 3 (see the detailed MFES block).

In this way, the multi-dimensional code feature information contained in the nodes is completely transformed into uniformly dimensioned feature vectors. Furthermore, this vertical hierarchical structure not only enhances the model’s feature extraction capability but also improves its scalability and adaptability, facilitating the subsequent addition of layers as needed to further supplement and refine node feature information.

The input to MNEN is the initial feature vector of each MDSG node obtained after processing in Section 4.1.1. Each code statement node \(v_i\) includes initial features across three dimensions: Sub-AST, PDG-Context, and ComCPG, which represent different levels of source code characteristics. Accordingly, for different dimensions of code features, this paper selects different neural networks for feature extraction, ultimately obtaining the feature sequence \(Y_i = [y_{i1}, y_{i2}, y_{i3}]\) for the statement node \(v_i\).

Common output dimension constraint

A critical prerequisite for the subsequent feature fusion stage is that the outputs from the three parallel feature extractors must have identical dimensions. To this end, we configure the Tree-LSTM (for Sub-AST) and the two GRUs (for PDG-Context and ComCPG) to each produce a fixed-length output vector of dimension \(d_{model}\). Formally, for a statement node \(v_i\), the feature extractors yield:

$$\begin{aligned} \textbf{y}_{i1}&= \text {Tree-LSTM}(\textbf{f}_{i1}) \in \mathbb {R}^{d_{model}} \end{aligned}$$
(10)
$$\begin{aligned} \textbf{y}_{i2}&= \text {GRU}_{\text {PDG}}(\textbf{f}_{i2}) \in \mathbb {R}^{d_{model}} \end{aligned}$$
(11)
$$\begin{aligned} \textbf{y}_{i3}&= \text {GRU}_{\text {ComCPG}}(\textbf{f}_{i3}) \in \mathbb {R}^{d_{model}} \end{aligned}$$
(12)

where \(\textbf{f}_{i1}, \textbf{f}_{i2}, \textbf{f}_{i3}\) are the initial feature vectors for the three dimensions as defined in Section 4.1.1. The common dimension \(d_{model}\) is a key hyperparameter; in our experiments (Section 5.4), \(d_{model}=256\).

The final feature sequence for node \(v_i\) is the concatenation of these three vectors:

$$\begin{aligned} \textbf{Y}_i = [\textbf{y}_{i1}; \textbf{y}_{i2}; \textbf{y}_{i3}] \in \mathbb {R}^{3 \times d_{model}} \end{aligned}$$
(13)

Specifically, for the PDG-Context and ComCPG information of code lines, MNEN employs GRU as the feature extraction network. This is because, although these two dimensions represent different semantic information, they can be regarded as specialized text sequences after being serialized into code tokens. GRU has proven highly effective in natural language processing tasks for capturing contextual information and semantic relationships within text sequences (Cho et al. 2014). Leveraging GRU’s advanced gating mechanism, the model can automatically and selectively focus on critical features in the code, effectively capturing the structure and patterns in the source code to extract meaningful features. For the abstract syntax tree dimension, MNEN adopts Tree-LSTM as the feature extraction network. Its effectiveness in handling tree structures has been extensively validated by previous researchers through numerous experiments, enabling it to efficiently extract the structural information and syntactic-semantic features of the current code statement node.

This one-to-one mapping of network models ensures that the multi-dimensional code feature information contained in the nodes is completely transformed into feature vectors. Furthermore, this vertical hierarchical structure not only enhances the model’s feature extraction capability but also improves its scalability and adaptability, facilitating the subsequent addition of layers as needed to further supplement and refine node feature information.

4.1.3 ABiGRU: multi-dimensional feature fusion network structure

Feature fusion across multiple dimensions has emerged as a promising strategy to significantly enhance detection performance in various applications. Currently, most studies mainly adopt two fusion methods: concat and add. Specifically, the concat method directly connects the feature vectors end-to-end through a serial strategy. Conversely, the add method employs a parallelized approach to merge feature vector pairs into complex-valued vectors. Here, it is necessary to fuse the three feature vectors extracted from each statement node to obtain a node feature vector with richer features.

To effectively integrate the multi-dimensional feature vectors extracted by MFES from each statement node, this study adopts ABiGRU as the feature fusion network. The input of the fusion network is the feature sequence \(Y_{i}=[y_{i1}, y_{i2}, y_{i3}]\) extracted by MNEN for the statement node \(v_i\) where \(i=1,2,\ldots ,n\), and n represents the overall number of nodes.

BiGRU processes the input feature sequence in both forward and backward directions, enhancing representation capability and reducing information loss. The core mechanism involves two GRU networks that extract hidden states from both directions. The forward hidden state \(g_{\overrightarrow{t}}\) and the backward hidden state \(g_{\overleftarrow{t}}\) are computed as shown in (14) and (15), where \(g_t\) represents the input sequence:

$$\begin{aligned} g_{\overrightarrow{t}} =f(c_t,g_{\overrightarrow{t}-1}) \end{aligned}$$
(14)
$$\begin{aligned} g_{\overleftarrow{t}} =f(c_t,g_{\overleftarrow{t}+1}) \end{aligned}$$
(15)

The final hidden state \(g_t\) is acquired by combining the forward and backward hidden states, as shown in (16). Here, \(m_t\) and \(n_t\) are the weights assigned to the forward and backward hidden states respectively at time step t, and \(b_t\) is the bias term.

$$\begin{aligned} g_t=m_t g_{\overrightarrow{t}}+n_t g_{\overleftarrow{t}}+b_t=[g_{\overrightarrow{t}},g_{\overleftarrow{t}}] \end{aligned}$$
(16)

The bidirectional hidden state sequence G produced by the BiGRU is processed through an attention mechanism. This module computes attention weights to highlight significant features across temporal steps, allowing the model to prioritize critical information and amplify feature interactions, thereby enhancing overall performance.

Let \(G = [g_1, g_2, g_3] \in R^{3 \times 2h}\) represent the stacked hidden state vectors from the BiGRU for the three feature-dimension steps, where h is the hidden size of a unidirectional GRU. The attention weights A are calculated per (17), where W and b denote trainable parameters. Here, the SoftMax function performs weight normalization while the \(\tanh \) activation injects non-linearity to augment model expressiveness:

$$\begin{aligned} A=SoftMax(tanh(GW+b)) \end{aligned}$$
(17)

Each hidden state vector is combined with its corresponding attention weight, and the weighted fusion generates a new feature vector. A fully connected layer then maps the fused feature vector to a lower-dimensional space, reducing model complexity. The process is defined in (18):

$$\begin{aligned} g_{vi}=fc(AP) \end{aligned}$$
(18)

where \(g_{v_i}\) represents the feature vector of node \(v_i\) after feature fusion, and fc denotes the fully connected layer.

Up to this point, before inputting into the graph network model for judgment, the semantic information in the code statements that is helpful for vulnerability detection has been converted into a source code graph structure representation, and the graph has been encoded into a node feature matrix \(g_{v}\in R^{n\times m}\) and an adjacency matrix \( A\in R^{n\times n}\), where n represents the number of nodes and m represents the dimension of the embedding vector.

Justification for using an order-sensitive fusion model

The three feature vectors \(\textbf{y}_{i1}, \textbf{y}_{i2}, \textbf{y}_{i3}\) are indeed logically parallel, representing different semantic views of the same code statement. One might argue that an order-insensitive model (e.g., a simple attention-based weighted sum or a small Transformer encoder) would be more natural. However, we intentionally employ the order-sensitive ABiGRU for two reasons:

  1. 1.

    Learning Complex Feature Interactions: While the features are parallel, their interactions are complex and hierarchical. Treating them as a fixed-order sequence allows the BiGRU to model conditional relationships and multi-step feature transitions that a simple aggregator might miss. The GRU’s gating mechanisms can learn to prioritize or modulate information flow from one feature dimension based on the state accumulated from previous dimensions in the sequence.

  2. 2.

    Empirical Superiority of a Canonical Order: Although any fixed order is arbitrary, we hypothesize that a consistent, well-chosen ordering allows the model to learn a stable and effective fusion function. The selected order [Sub-AST, PDG-Context, ComCPG] reflects a progression from syntactic structure (Sub-AST), to intra-procedural semantic dependencies (PDG-Context), to inter-procedural and broader contextual relationships (ComCPG). This ordering provides a coherent inductive bias. To validate that the model’s performance is not brittle to this choice, we conduct an ablation experiment (Section 6.2) where we permute the input order, demonstrating the robustness of the approach and the advantage of our chosen sequence.

Suitability of ABiGRU for multi-dimensional feature fusion Having established the rationale for using an order-sensitive model, we now explain why the Attention-based Bidirectional GRU (ABiGRU) is particularly compatible with the specific features we aim to fuse.

The three feature vectors—representing syntax (\(\textbf{y}_{i1}\)), intra-procedural dependencies (\(\textbf{y}_{i2}\)), and inter-procedural context (\(\textbf{y}_{i3}\))—are complementary but inherently heterogeneous. A simple aggregator (e.g., weighted sum) might struggle to model the complex, non-linear interactions between these distinct semantic views. The ABiGRU architecture offers two key advantages tailored to this challenge:

  1. 1.

    Adaptive, Gated Information Flow: The GRU’s core gating mechanism (update and reset gates) allows the model to adaptively control how much information from each incoming feature dimension should be preserved, combined with, or overwritten by the existing hidden state. This is crucial because the relative importance of syntactic structure vs. data-flow dependencies vs. function-call context may vary significantly across different code statements or vulnerability patterns. The GRU learns to dynamically adjust this fusion strategy.

  2. 2.

    Bidirectional Context for Feature Reconciliation: The bidirectional processing enables the fusion network to look at the entire feature sequence from both directions when synthesizing the representation for each step. This is analogous to reconciling information from all three feature dimensions simultaneously, helping to resolve potential conflicts or reinforce consistent signals between, for example, a syntactic pattern (AST) and its data-flow implications (PDG).

The attention mechanism layered on top of the BiGRU output further refines this process by learning to assign importance weights to different steps (i.e., different feature dimensions) within the context of the specific code sample, providing a second level of adaptive fusion.

Therefore, the ABiGRU acts not merely as an aggregator but as a learned fusion function that exploits the sequential processing capacity of RNNs to synthesize a unified representation from multiple unordered-but-related inputs.

4.2 AMF-RGCN

In this section, we propose an improvement strategy, AMF-RGCN, aiming to achieve deep extraction of global semantic features in code through hierarchical graph structure modeling. Specifically, we first preserve the node feature vectors (\(g_v\)) generated in the previous section 4.1 while independently initializing embeddings for edge direction and edge type, thereby constructing a type-sensitive heterogeneous graph representation. During network propagation, each RGCN layer aggregates neighboring node information along different edge types via relation-specific weight matrices and integrates the aggregated results with the central node features through feature concatenation. After transformation by an activation function (ReLU in this work), the model iteratively generates high-order structure-aware node representations.

4.2.1 Edge embedding

In this section, different embedding methods are used for edge directions and edge types respectively to generate initial vectors. For edge directions, DFS is employed to sort the nodes and number them starting from 0. The edge directions are then encoded in the form of pairs of node numbers.

$$\begin{aligned} D_{Edge} = \left\{< v_i.order,v_j.order> \mid e= < v_i,v_j > ,e\in Edge(CG) \right\} \end{aligned}$$
(19)

Regarding edge types, label encoding is employed to encode the finite edge types.

$$\begin{aligned} T_{Edge} = \left\{ t_e\mid e\in Edge(CG) \right\} \end{aligned}$$
(20)
$$\begin{aligned} t_e=\left\{ \begin{matrix}6 & if e.type = PDG\\ 5 & if e.type = CDG\\ 4 & if e.type = DDG\\ 3 & if e.type = AST\\ 2 & if e.type = CFG\\ 1 & if e.type = FCG\\ 0 & if e.type = NCS\end{matrix}\right. \end{aligned}$$
(21)

4.2.2 Graph convolutional layer

As illustrated in Fig. 10, node updates within each RGCN layer require aggregating neighbor information according to edge types. This aggregated data is then fused with the node’s intrinsic features and processed through a ReLU activation function to derive the final representation.

The vector of a single node will be updated according to the following (22).

$$\begin{aligned} p_{i3}^{(k+1)} = p_{i3}^{(k)} + \sum _{w\in W} \sum _{v_j\in Vertex_{w}^{j} } \frac{1}{Vertex_{w}^{j}} \gamma (R_w[p_{i3}^{(k)},p_{j3}^{(k)},D_{i,j},T_{i,j}]+c_w) \end{aligned}$$
(22)

Here, \(\gamma (\cdot )\) represents the non-linear activation function ReLU. W represents the set of edge types, and w represents one of the corresponding seven edge relationships. \(Vertex_{w}^{j}\) represents the set of nodes adjacent to the current node under the current relationship w. \(D_{i,j}\in D_{Edge}\), \(T_{i,j}\in T_E\) represent the edge direction and edge type between nodes \(v_i\) and \(v_j\) respectively. \(R_w\) and \(c_w\) represent the learnable parameters, and \(p_{i3}^{(k+1)}\) represents the final state of the updated node.

4.2.3 Feature fusion layer

By stacking multiple layers of graph convolution, a GCN can extract deep node features and expand the range of information interaction. However, as the number of layers increases, node features tend to converge toward the average of their neighbors, potentially reducing their distinctiveness. Relying solely on the top-layer node features for graph representation may compromise the overall quality of graph representations and degrade classification performance.

As depicted in Fig. 11, assume the model contains K layers of RGCN, with node feature vectors generated at each layer denoted as \( g_{v}^{k}\), \(k=1,2,\dots ,K \). First, attention weights \(A_k\) are assigned to each layer using a self-attention mechanism. Next, these weights are multiplied by their corresponding feature vectors \( g_{v}^{(k)}\) and summed to obtain the fused final node features. Finally, global graph features \(g_{CG}\) , representing the entire program, are computed using mean graph pooling. The process of attention weight computation and feature fusion is defined by (23) and (24) :

$$\begin{aligned} A_k=SoftMax(W_2\cdot \gamma (W_1\cdot g_v^{(k)})) \end{aligned}$$
(23)
$$\begin{aligned} g_{CG}=MeanPool(\sum _{k=1}^{K}A_k\cdot g_v^{(k)})) \end{aligned}$$
(24)

where \(W_1\) and \(W_2\) are trainable parameter matrices, \(\gamma (\cdot )\) is an activation function, and SoftMax is the normalization function.

4.3 Feature classification

The feature classification stage is the final phase of the model, tasked with determining whether the input function sample contains a vulnerability. This is framed as a binary classification problem.

A fully connected layer coupled with a SoftMax layer is employed for classification. The fully connected layer compresses the feature space dimensionality to align with the two target categories, after which the SoftMax function computes the probability distribution across both classes to yield the final classification outcome.

4.4 Complexity analysis of AMF-RGCN

The complexity analysis of AMF-RGCN primarily involves two dimensions: time complexity and space complexity, whose calculations depend on the design of the model’s key components and the scale of input data. In terms of time complexity, we first consider the edge embedding module, which mainly includes edge direction encoding based on node ordering and label encoding of edge types. Node ordering is implemented via DFS, resulting in a time complexity of \(O(N+E)\) (where N is the number of nodes and E is the number of edges). The encoding processes for edge directions and types are both linearly related to the number of edges, leading to an overall time complexity of \(O(N+E)\) for the edge embedding stage. After entering the RGCN layers, the model aggregates neighbor information across different edge types using relation-specific weight matrices. Assuming the total number of edge types in the graph is R (\(R=7\) according to the model design), each RGCN layer has a hidden dimension H, and the average number of neighbors per node is d (\(d=E/N)\), the time complexity of a single RGCN layer is \(O(R \cdot E \cdot H)\): for each edge, feature transformation is performed using a relation weight matrix (of dimension \(H \times H\)), and aggregation operations are executed on the d neighbors of each node, involving computations on H-dimensional vectors. If the model stacks K RGCN layers, the total time complexity of the RGCN component becomes \(O(K \cdot R \cdot E \cdot H)\). The feature fusion layer employs a self-attention mechanism to perform weighted fusion of node features from K layers, where the calculation of attention weights involves two layers of linear transformations (with dimension \(H \times H\)), resulting in a time complexity of \(O(K \cdot N \cdot H)\). Weighted summation and average pooling operations are also related to the number of nodes and hidden layer dimension, leading to an overall time complexity of \(O(K \cdot N \cdot H)\) for the feature fusion stage. Integrating all modules, the total time complexity of AMF-RGCN is dominated by the RGCN layers, ultimately expressed as \(O(K \cdot R \cdot E \cdot H + K \cdot N \cdot H + N+E)\), which can be simplified to \(O(K \cdot R \cdot E \cdot H)\) in large-scale graphs, where E is the primary influencing factor.

In terms of space complexity, the model parameters mainly include learnable vectors for edge embedding, relation-specific weight matrices in RGCN layers, and attention parameters in the feature fusion layer. For edge embedding, the dimensions of the embedding matrices for edge directions and types are \(O(V_dir \cdot H_e)\) and\( O(V_type \cdot H_e)\) respectively (where \(V_dir\) is the vocabulary size of node order pairs, \(V_type\) is the number of edge types, and \(H_e\) is the edge embedding dimension). However, in practical applications, dynamic encoding is used to avoid explicit storage of large-vocabulary embedding tables, so the space complexity of edge embedding can be simplified to \(O(E \cdot H_e)\) (storing the embedding vector for each edge). In the RGCN layers, each layer contains R weight matrices (each of dimension \(H\times H\)), leading to a parameter scale of \(O(K \cdot R \cdot H^2)\) for K layers. The attention parameters in the feature fusion layer include two linear transformation matrices (\(W1\in R^{H \times H}\), \(W2\in R^{H \times 1}\)), with a space complexity of O(H\(^2\)). Furthermore, the model needs to store node features from K RGCN layers, resulting in a space complexity of \(O(K \cdot N \cdot H)\). Overall, the space complexity of AMF-RGCN is jointly determined by parameter storage and intermediate features, expressed as \(O(K \cdot R \cdot H^2 + K \cdot N \cdot H + E \cdot H_e)\), where K, R, and H are the main influencing parameters. When the graph scale is large (with increased N and E), the storage of intermediate features \((O(K \cdot N \cdot H))\) becomes the dominant factor in space complexity.

5.1 Research question

We consider three different aspects to formulate the research questions in this paper, aiming to evaluate the code vulnerability detection performance of the MDFVD model. The proposed questions are as follows:

QR1: How does our approach fare when compared with the current state-of-the-art baselines?

5.2 Datasets

This study focuses on C vulnerability detection by conducting evaluations on two types of datasets: standardized synthetic samples and real-world project collections.

5.2.1 SARD: standardized synthetic samples

The first dataset employed in this study is derived from the Software Assurance Reference Dataset (SARD), a globally recognized benchmark resource meticulously maintained by the National Institute of Standards and Technology, an agency renowned for its authoritative role in establishing technical standards across various domains, including cybersecurity and software engineering.

As a cornerstone of software security evaluation frameworks, SARD distinguishes itself through its rigorous construction process, which involves the development of manually-crafted test cases and synthetic vulnerability examples by a team of expert security researchers and software engineers. This meticulous curation ensures a high degree of precision in vulnerability representation, with each test case undergoing thorough validation to align with the official Common Weakness Enumeration (CWE) definitions and real-world attack patterns.

What truly sets SARD apart from other datasets in the field is its unique architectural design that provides paired vulnerable functions alongside their corresponding patched versions–a feature that is invaluable for vulnerability detection research. This binary structure not only enables researchers to isolate the specific code changes that mitigate vulnerabilities but also allows for the systematic evaluation of detection models’ ability to distinguish between exploitable flaws and their remediated counterparts, thereby establishing an optimal benchmark for assessing both false positive rates and true vulnerability identification accuracy.

In constructing our experimental dataset, we adhered to the most current industry guidelines by aligning with the 2024 CWE Top 25 list of the most critical security weaknesses, which reflects the evolving threat landscape and prioritizes vulnerabilities that pose the highest risk to software systems.

Additionally, we followed the methodological precedents set by seminal research in the field, such as the work by Wang et al. (2020), to ensure compatibility and comparability with existing literature. Through this careful selection process, we assembled a comprehensive SARD subset that includes 9,841 vulnerable functions and 18,698 secure functions, creating a balanced and representative sample that covers a wide spectrum of vulnerability types and severity levels, as detailed in Table 2. This subset not only captures the diversity of common security flaws but also maintains the statistical integrity necessary for robust model training and evaluation, making it an ideal foundation for assessing the effectiveness of our proposed vulnerability detection approach.

This subset encompasses critical vulnerabilities that collectively represent the most pressing threats to software systems, each characterized by distinct technical mechanisms and far-reaching security implications.

CWE-78 (OS Command Injection) enables attackers to inject and execute arbitrary operating system commands by crafting malicious inputs that exploit insufficiently sanitized command-line interfaces, often leading to full system compromise through unauthorized access to sensitive data, privilege escalation, or the deployment of malware within the target environment.

CWE-416 (Use After Free) arises when a program continues to reference memory after it has been deallocated, creating a critical security flaw that can be exploited to hijack control flow, corrupt memory structures, or execute arbitrary code by manipulating the reuse of freed memory blocks, thereby undermining the integrity of the application’s memory management.

CWE-476 (NULL Pointer Dereference) occurs when a program attempts to access memory through a NULL pointer, typically resulting in immediate application crashes, denial-of-service conditions, or the exposure of system instability that can be leveraged to bypass security checks or trigger unexpected behavior in complex software architectures.

CWE-190 (Integer Overflow or Wraparound) manifests when arithmetic operations exceed the maximum or minimum value limits of an integer data type, leading to value wraparound that can corrupt memory allocations, distort logical conditions, or facilitate buffer overflows by miscalculating the size of data structures, thereby compromising the reliability of size-dependent operations.

CWE-121 (Stack-Based Buffer Overflow) involves the overwriting of stack memory beyond the boundaries of allocated buffers, enabling attackers to overwrite return addresses, manipulate function pointers, or inject malicious code into the call stack, which can redirect program execution to attacker-controlled payloads and bypass memory protection mechanisms such as stack canaries or address space layout randomization.

CWE-758 (Undefined Behavior) encompasses a range of compiler-dependent anomalies arising from non-standard code constructs, such as uninitialized variable usage, out-of-bounds array access, or improper type casting, which can manifest as unpredictable program behavior, silent data corruption, or the introduction of hidden vulnerabilities that evade detection during testing but may be exploited in production environments.

CWE-122 (Heap-Based Buffer Overflow) targets dynamically allocated memory regions, allowing attackers to corrupt heap metadata, overwrite adjacent memory blocks, or execute arbitrary code by manipulating the allocation and deallocation of heap buffers, a technique frequently employed to bypass heap protection mechanisms and gain unauthorized access to system resources.

Finally, CWE-134 (Uncontrolled Format String) exploits improper handling of format specifiers in functions such as printf() or fprintf(), enabling attackers to read arbitrary memory, write to specific addresses, or execute code by passing malicious format strings that manipulate the program’s stack or register state, thereby compromising the confidentiality and integrity of sensitive information stored in memory. Together, these vulnerabilities span critical categories of memory corruption, input validation failures, and arithmetic errors, representing the core challenges in secure software development and the primary attack surfaces targeted by modern cyber threats.

To prevent the omission of CWE categories in different data subsets, during the dataset partitioning, each CWE type was split into the training set, validation set, and test set at an 8:1:1 ratio.

Construction of FCG edges

The Reveal, Fan’s Big-Vul, and FFmpeg+QEMU datasets provide isolated, function-level code snippets. Therefore, a full, project-wide FCG cannot be constructed. The FCG edges in the ComCPG for these datasets are intra-procedural, derived from function calls within the given function snippet to other functions (external library functions or user-defined functions whose bodies are not present in the snippet). These edges are vital for representing the call context present in the code, even if the callee’s full implementation is unknown. For the SARD dataset, where multiple related functions (vulnerable and patched versions) are extracted from the same test case, we construct a localized FCG among those functions to better simulate a modular context. This approach is consistent with the standard evaluation setting for learning-based vulnerability detection.

Note on evaluation scope and “global” information

The benchmark datasets used (Reveal, Fan’s Big-Vul, FFmpeg+QEMU, SARD) provide labels at the function level. This is the standard granularity for evaluating learning-based vulnerability detection models (Zhou et al. 2019; Chakraborty et al. 2021). Therefore, our evaluation tests MDFVD’s ability to correctly classify entire functions as vulnerable or benign. In this context, the term global semantic information refers to the comprehensive structural and semantic patterns distributed across the entire code segment of a single function, which the AMF-RGCN component is designed to learn from the integrated graph. This is contrasted with the local information of individual statements extracted by MFES. The use of function-level datasets is thus appropriate and does not undermine the evaluation; rather, it validates that our model can effectively synthesize intra-procedural global context to perform the standard function-level classification task.

5.3 Evaluation metrics

Vulnerability detection is a classic binary classification task. The results fall into two classes: 0 for no vulnerability and 1 for the presence of a vulnerability. In the detection process, four possible results are taken into account. True Positive (TP) is the number of samples accurately identified as vulnerable. False Positive (FP) is the number of samples wrongly predicted as vulnerable while they are actually not. True Negative (TN) is the number of samples correctly recognized as non-vulnerable. False Negative (FN) is the number of samples misclassified as non-vulnerable but are actually vulnerable.

In the realm of source code vulnerability detection, frequently employed evaluation metrics are Accuracy, Precision, Recall, and the F1-score. These metrics are all calculated based on TP, FP, TN, and FN.

Accuracy: \(Accuracy=\frac{TP+TN}{TP+TN+FP+FN}\). Accuracy measures the proportion of correctly predicted samples to the total samples.

Precision: \(Precision=\frac{TP}{TP+FP}\). Precision indicates the proportion of correctly identified vulnerabilities among all samples predicted as vulnerable.

Recall: \(Recall=\frac{TP}{TP+FN}\). Recall evaluates the proportion of actual vulnerabilities that are correctly detected.

F1-score: \(F1=\frac{2\times Precision\times Recall}{Precision+Recall}\). F1-score, which is a weighted harmonic average of Precision and Recall, offers a well-balanced assessment of the model’s classification performance.

To ensure the comparability and readability of results, all performance metrics (Accuracy, Precision, Recall, F1-score, TPR, FPR, G-mean, MCC) in the tables of this paper are uniformly retained to four decimal places.

6.1.1 Supplementary evaluation metrics

In order to evaluate the model performance more comprehensively, besides the evaluation metrics proposed above, this paper needs to consider various factors in the actual production environment. Therefore, this paper introduces TPR, FPR, AUC, G-mean, and MCC as supplementary evaluation metrics. Compared with a single metric, these comprehensive evaluation methods can more effectively reduce the impact of data distribution changes on model performance, objectively reflect the model’s recognition ability under different sample conditions, and help characterize the generalization ability of the detection model and its application effect in actual deployment.

TPR measures the model’s ability to identify “positive cases”, that is, “the percentage of true positives among actual positives”. FPR measures the model’s misjudgment probability of “negative cases”, that is, “the percentage of false positives among actual negatives”. Their formulas are as follows:

$$\begin{aligned} TPR=\frac{TP}{TP+FN} \end{aligned}$$
(25)
$$\begin{aligned} FPR=\frac{FP}{FP+TN} \end{aligned}$$
(26)

AUC is an indicator used to measure the performance of binary classification models, and it is usually used to evaluate the performance of ROC curves. The formula for calculating AUC is as follows:

where, \(TP_i\) represents the number of true positives at the \(i-th\) threshold, \(\bigtriangleup FPR_i\) represents the change in false positive rate at the \(i-th\) threshold, and \(\bigtriangleup TPR_i\) represents the change in true positive rate at the \(i-th\) threshold. The calculation formulas for TPR and FPR are as follows:

$$\begin{aligned} AUC = \frac{ {\textstyle \sum _{i=1}^{n}(TP_{i}\times \bigtriangleup FPR_{i})+\sum _{i=2}^{n}(TP_{i}\times \bigtriangleup TPR_{i})} }{2} \end{aligned}$$
(27)

The G-mean metric is commonly used to evaluate classification models in the case of imbalanced samples. Its value is the geometric mean of specificity and recall. This metric comprehensively considers the model’s ability to predict both positive and negative classes, ensuring the balance of classification results among different classes. A higher value indicates better classification performance, and its calculation formula is as follows:

$$\begin{aligned} G-mean = \sqrt{\frac{TP}{TP+FN}\times \frac{TN}{TN+FP}} \end{aligned}$$
(28)

MCC is an indicator for evaluating the performance of binary classification models, especially suitable for handling imbalanced datasets. This metric comprehensively considers TP, TN, FP, and FN to assess model performance. By integrating all prediction results of positive and negative classes, it reflects the linear correlation between the model’s predicted values and actual values. Its value ranges from -1 to 1, where 1 represents perfect prediction, 0 indicates performance equivalent to random prediction, and -1 means the prediction is completely inconsistent with the actual values. The calculation formula is as follows:

$$\begin{aligned} MCC = \frac{(TP\times TN)-(FP\times FN)}{(TP+FP)(TP+FN)(TN+FP)(TN+FN)} \end{aligned}$$
(29)

6.1.2 Runtime efficiency analysis

Runtime efficiency is evaluated from two perspectives: training time and inference speed. In terms of training time, MDFVD generally requires longer per-epoch training time across datasets compared to traditional static analysis methods (e.g., Russell and VulDeePecker), due to its incorporation of a 3-layer graph convolutional structure and higher-dimensional hidden states (256 dimensions). However, the difference is minimal when compared to other deep learning models of the same type (e.g., Devign and Reveal). For instance, on the Reveal dataset, MDFVD requires approximately 1.8 hours per epoch, slightly longer than Reveal’s 1.6 hours (with a 7.63% improvement in accuracy), but significantly shorter than SySeVR’s 2.2 hours (despite SySeVR achieving only 0.7214 accuracy). On the Fan’s Big-Vul dataset, MDFVD’s per-epoch training time is 2.1 hours, which is about 10.5% longer than Devign (1.9 hours), but it achieves a 21.25% improvement in F1-score, demonstrating a favorable trade-off between performance and efficiency. For large-scale datasets such as FFmpeg+QEMU and SARD, MDFVD’s training times are 2.5 hours/epoch and 2.3 hours/epoch, respectively, primarily due to increased sample sizes leading to longer data loading and forward propagation times. Nevertheless, the total training time for 600 epochs remains within a reasonable range. Additionally, GPU parallel computing (CUDA acceleration with RTX 4070) improves training efficiency by approximately 4.2 times compared to CPU training.

In terms of inference speed, MDFVD demonstrates high real-time performance in single-sample vulnerability detection. On the Reveal dataset, its average inference time is 0.42 seconds per sample, slightly higher than Russell (0.31 seconds per sample) and VulDeePecker (0.35 seconds per sample), but significantly better than Devign (0.58 seconds per sample) and Reveal (0.51 seconds per sample). This advantage stems from the optimized design of MDFVD’s graph convolutional layers, which reduces redundant connections and leverages efficient computation of ReLU activation functions, thereby minimizing time overhead during the feature extraction phase.

Effect of AMF-RGCN

We conducted an ablation study to evaluate AMF-RGCN’s contribution. In NLP and code representation domains, three prevalent GNN architectures are typically employed: Recurrent GNNs (e.g., GGNN), Spectral-based Convolutional GNNs (e.g., GCN), and Spatial-based Convolutional GNNs (e.g., GAT) (Wu et al. 2020). We developed three variants by replacing AMF-RGCN with these baseline architectures:

MDFVD-GGNN: Encodes ComCPG using GGNN. Replaces AMF-RGCN with a GGNN (Li et al. 2015). The GGNN uses a GRU in the propagation step, making it inherently deep and suitable for capturing sequential dependencies across nodes. To handle multiple edge types in ComCPG, we sum the messages from neighbors across all edge types before the GRU update, effectively treating the graph as homogeneous.

MDFVD-GCN: Encodes ComCPG using GCN. Replaces AMF-RGCN with a standard GCN (Kipf and Welling 2016). The GCN performs a simple, fixed neighborhood aggregation. To accommodate multiple relations, we again sum the features from neighbors across all edge types, ignoring edge type distinctions during aggregation.

MDFVD-GAT: Encodes ComCPG using GAT. Replaces AMF-RGCN with a GAT (Velickovic et al. 2017). GAT uses an attention mechanism to weight the importance of neighboring nodes. For our multi-relational graph, we compute attention weights independently for each edge type and then average the resulting weighted neighbor features, providing a basic form of relation-aware aggregation.

These variants maintain the same node feature input from MFES but differ fundamentally in how they propagate and aggregate information across the graph. Crucially, unlike AMF-RGCN, none of them employ relation-specific weight matrices for different edge types or the attention-based multi-layer feature fusion mechanism, which are the core innovations of our proposed architecture.

Effect of feature order in ABiGRU

To address the concern regarding the order-sensitivity of the ABiGRU fusion module, we introduce a variant:

MDFVD-Permuted: The concatenated feature sequence \(Y_i = [y_{i1}, y_{i2}, y_{i3}]\) is permuted to a different fixed order (specifically \([y_{i2}, y_{i3}, y_{i1}]\)) before being fed into the ABiGRU. This tests the robustness of the fusion to the canonical ordering.

6.2.2 Experimental results

Effect of feature channels

Table 9 compares the performance of MDFVD-A, MDFVD-P, MDFVD-C, MDFVD-AP, MDFVD-AC, and MDFVD-PC with our full model. The results demonstrate that MDFVD significantly outperforms all six variants, achieving over 32% higher metrics than single-channel variants and exceeding dual-channel variants by more than 9% across all evaluation criteria. Single-channel variants (MDFVD-A, MDFVD-P, MDFVD-C) show comparable performance with negligible differences, suggesting no single channel dominates effectiveness. To quantify the benefit of adding a second feature channel, we compare the best single-channel F1-score (e.g., 0.3937 for MDFVD-C on Reveal) with the worst dual-channel F1-score (e.g., 0.4410 for MDFVD-AP on Reveal) on each dataset. The minimum improvement observed is 12.0% (Reveal: (0.4410-0.3937)/0.3937 \(\approx \) 12.0%). Dual-channel variants exhibit over 12% F1-score improvement compared to single-channel configurations, confirming the complementary nature of different feature channels. The progressive performance enhancement from single-channel to triple-channel configurations validates the necessity of our multi-channel approach.

Effect of NCS and FCG edges in ComCPG

Table 9 presents the fine-grained ablation results dissecting the contributions of the two novel edge types in ComCPG. Both NCS and FCG edges provide substantial individual improvements over the Standard CPG baseline. On the Reveal dataset, adding only NCS edges (MDFVD-CPG+NCS) improves the F1-score by 12.0% (from 0.4301 to 0.4819), while adding only FCG edges (MDFVD-CPG+FCG) yields a 15.7% improvement (from 0.4301 to 0.4975). This confirms that FCG edges provide a stronger individual boost on this dataset, likely due to its emphasis on inter-procedural vulnerabilities. The trend is consistent across datasets: FCG edges show a larger average individual contribution (10.7% on SARD) compared to NCS edges (6.1% on SARD), indicating their broader impact on enhancing code representation. The full ComCPG consistently outperforms all partial variants, achieving an additional 3.6–4.4% F1 improvement over the best single-edge-augmented variant. This demonstrates that NCS and FCG edges are not redundant; they capture complementary aspects of code structure–NCS edges enrich local lexical flow and basic block connectivity, while FCG edges introduce crucial inter-procedural context–and their combination yields a synergistic benefit greater than the sum of their individual contributions. Therefore, while FCG edges generally provide a larger individual performance gain, the major role is played by the strategic integration of both edge types. This fine-grained ablation confirms that both novel components of ComCPG are valuable and that their complementary integration is key to its superior performance across diverse vulnerability detection scenarios.

Effect of MFES

Table 9 compares the performance of two variants, MDFVD-Reveal and MDFVD-Devign, with the complete MDFVD model. The results demonstrate that MDFVD outperforms both variant models across all evaluation metrics. Specifically, compared to MDFVD-Reveal, MDFVD achieves average improvements of 6.45% in accuracy and 11.87% in F1-score across all datasets, while compared to MDFVD-Devign, it shows average improvements of 7.61% in accuracy and 21.44% in F1-score. These findings confirm the effectiveness of MDFVD’s feature extraction method, MFES, thereby validating the necessity of adopting MFES.

Effect of AMF-RGCN

Table 9 also presents the comparative performance of MDFVD-GGNN, MDFVD-GCN, MDFVD-GAT, and MDFVD on four datasets. Compared with the best-performing network variants, our method improves the F1-score by 9.41%, 25.27%, 4.32%, and 15.02% respectively, and increases the accuracy by 7.93%, 15.65%, 8.70%, and 6.23% respectively. This superiority stems from AMF-RGCN, which can dynamically assign layer-wise attention weights. It effectively integrates multi-level features while preserving the distinctiveness of nodes and alleviating the over-smoothing problem. Although the performance of GCN is lower than that of GGNN/GAT, its higher training efficiency comes from the parameter-efficient neighborhood aggregation. AMF-RGCN combines the efficient local propagation of GCN with adaptive attention-based fusion, achieving an optimal balance between computational efficiency and detection capability.

Effect of feature order in ABiGRU

We further investigate the impact of input order sensitivity by evaluating the MDFVD-Permuted variant, where the feature sequence is rearranged to [PDG-Context, ComCPG, Sub-AST]. As shown in Table 9, permuting the order leads to a consistent but moderate performance drop across all datasets (F1-score decreases of 3.00%, 2.22%, 1.89%, and 1.85% on Reveal, Fan’s Big-Vul, FFmpeg+QEMU, and SARD, respectively). This confirms that the ABiGRU fusion module is indeed sensitive to the input order. Importantly, the performance of MDFVD-Permuted remains substantially higher than all single-channel and dual-channel variants, and the observed degradation is limited. This demonstrates that: (1) the fusion mechanism is robust and does not collapse under order variation; and (2) our canonical ordering [Sub-AST, PDG-Context, ComCPG] provides an empirically optimal inductive bias, justifying the use of an order-sensitive sequence model for fusing these logically parallel features.

Effect of ComCPG optimization on detection performance

A critical concern is whether the edge pruning strategy harms vulnerability detection accuracy. We evaluate the F1-score of MDFVD using the fully optimized ComCPG (incremental update + pruning) on the SARD test set. The result is 0.8034, representing a decrease of only 0.0187 (or 2.3%) compared to the F1-score of 0.8221 obtained with the original, unpruned ComCPG (Table 4). This marginal loss confirms that the pruned edges are indeed low-risk and that the optimization successfully maintains the model’s detection capability while dramatically improving scalability.

6.3 RQ3: performance on different types of vulnerabilities

To conduct an in-depth analysis of MDFVD and baseline methods’ performance in detecting various vulnerability types, we first partitioned the SARD test set into smaller subsets based on CWE classifications and evaluated their effectiveness on each category. As illustrated in Fig. 15, which compares the performance across eight distinct CWE types, all methodologies except REVEAL demonstrated exceptional performance in identifying CWE-758 vulnerabilities (Undefined Behavior). This category primarily stems from accessing variables prior to their initialization. Most detection approaches effectively capture structural information from function code and track variable definition-usage patterns, enabling successful identification of such vulnerabilities.

In contrast, all methods exhibited notably suboptimal performance for CWE-190 (Integer Overflow or Wraparound). This consistent difficulty across models points to fundamental challenges inherent in the vulnerability type itself, rather than a flaw in a specific model architecture. CWE-190 vulnerabilities require reasoning about the runtime values or value ranges of variables to determine if an operation (e.g., addition, multiplication) can exceed the data type’s limits. Our model, like all baselines, operates on a static graph representation (ComCPG) that captures syntactic structure, control flow, and data dependencies, but cannot infer concrete or symbolic values that variables may hold during execution. Without value analysis, it is exceptionally difficult to distinguish a benign integer operation from a vulnerable one based on structure alone. This explains the universal performance bottleneck.

Conversely, MDFVD demonstrates considerable advantages in identifying vulnerabilities such as CWE-121 (Stack-Based Buffer Overflow), CWE-416 (Use After Free), and CWE-758. For each of these types, MDFVD achieves an accuracy, precision, recall, and F1-score all exceeding 0.8. These vulnerabilities are primarily characterized by identifiable structural or pattern-based flaws: improper buffer indexing, mismanagement of pointer lifetimes, or access to uninitialized memory. The ComCPG excels at representing the intricate DDG, control flow, and object lifetime relationships necessary to detect these patterns. The AMF-RGCN’s ability to propagate information across these relational edges allows it to effectively learn these structural signatures.

Nevertheless, MDFVD demonstrated suboptimal performance in detecting CWE-190 (Integer Overflow or Wraparound), CWE-78 (OS Command Injection), and CWE-134 (Format String Vulnerability) vulnerabilities. This performance gap primarily arises from the inherent challenges posed by these vulnerability categories-their subtle manifestation patterns create significant learning obstacles, compounded by the requirement to comprehend complex computational patterns involving intricate parameter value derivations and external system interactions that exceed current architectural capabilities. A representative case is CWE-190 detection, which demands precise anticipation of integer operation overflows through sophisticated data flow analysis and value range prediction, capabilities that existing static analysis models fundamentally lack due to their limited capacity to track dynamic computational states without runtime execution.

Answers to RQ3: MDFVD demonstrates considerable advantages in identifying vulnerabilities such as CWE-121, CWE-416, and CWE-758. For each type of these vulnerabilities, MDFVD’s accuracy, precision and recall all exceed 0.8.

7 Discussion

This section synthesizes the key findings of the proposed MDFVD model, including its performance characteristics, experimental validation, and inherent limitations, to provide a comprehensive understanding of its scientific contributions and future improvement directions. First, we systematically discuss the effectiveness of MDFVD in function-level vulnerability detection, focusing on its innovative feature extraction mechanisms, comparative performance advantages, and generalization capabilities. Subsequently, we analyze potential threats to the validity of the research and identify limitations that need to be addressed in future work.

7.1 The effect of MDFVD

In this study, we propose a novel vulnerability detection model, MDFVD, to detect function-level vulnerabilities. MDFVD leverages MFES in combination with ABiGRU to extract the local semantic information embedded in each statement within the intermediate code representation. Moreover, it captures the global feature information of the entire code segment through AMF-RGCN. As a result, it can more comprehensively extract vulnerability features and enhance the final ability to judge vulnerabilities.

Extensive experiments on benchmark datasets validate the superiority of MDFVD. Our research provides a systematic multi-perspective evaluation of the MDFVD model’s vulnerability-detection capabilities. Specifically, comparative experiments with existing vulnerability-detection approaches demonstrate MDFVD’s effectiveness. Across all datasets, our method outperforms all baseline methods in terms of both accuracy and F1-score. Notably, on the four datasets, MDFVD elevates the F1-score by 15.15%, 21.25%, 9.43% and 14.67%, respectively, over the best-performing baselines, while increasing accuracy by 7.63%, 9.69%, 8.59% and 9.70%, respectively.

In addition, ablation experiments construct numerous variants of MDFVD. The performance of MDFVD is basically superior to its variants, which verifies the effectiveness of MFES and AMF-RGCN in MDFVD.

Experiments conducted on different types of vulnerability datasets split from SARD showcase the strong generalization ability of MDFVD. It demonstrates considerable advantages in identifying vulnerabilities such as CWE-121, CWE-416, and CWE-758. For each type of these vulnerabilities, the accuracy, precision, recall, and F1-score of MDFVD all exceed 0.8.

7.2 Threats and limitations

The initial threat to the effectiveness stems from the restricted quantity of experimental datasets. We carried out an evaluation of MDFVD on three datasets. The primary reason is that these three datasets have been frequently employed in previous works related to vulnerability detection (Chakraborty et al. 2021; Zhou et al. 2019) and (Qiu et al. 2024). Although the employed datasets cover a wide variety of open-source project types, future work will incorporate additional datasets to further validate MDFVD’s effectiveness.

The second limitation pertains to the scope of programming languages evaluated. Our experiments were exclusively tested on C/C++ datasets, omitting other languages such as Java. Future investigations will utilize datasets spanning a broader spectrum of programming languages for comprehensive assessment.

The third limitation originally pertained to the computational overhead and scalability of ComCPG in large-scale codebases. In response to reviewer feedback, we have designed and implemented a Layered Incremental Update Algorithm and an Edge Pruning Strategy (Section 2.3.5). Experimental validation on industrial-scale codebases (Linux Kernel and FFmpeg) shows that these optimizations reduce graph generation time by approximately 75% and memory usage by 50%, with a negligible impact on detection performance (F1-score loss \(\le \) 2.3%). These enhancements significantly mitigate the original scalability concern, making MDFVD more applicable to industrial scenarios. Future work could explore distributed graph generation for even larger code repositories.

The fourth potential limitation concerns the implementation specifics of the baseline models. As Devign (Zhou et al. 2019) didn’t make its implementation details and hyper-parameters public, we reproduced Devign following the implementation described in Wen et al. (2023). Through our best efforts in parameter adjustment, we achieved experimental results comparable to those reported in their paper.

7.3 Future work

Future work will focus on the following key directions to advance the capabilities and applicability of MDFVD:

Dataset expansion and validation

We will construct a multi-source, large-scale, and dynamically updated vulnerability dataset by integrating data from industrial projects, authorized closed-source reports, and platforms like CVE Details, with periodic injection of newly disclosed vulnerabilities to adapt to emerging attack patterns. Furthermore, we will enhance baseline model validation by collaborating with authors of state-of-the-art models to obtain official implementations or verified hyperparameters, and publish reproduction code for models without public resources to ensure rigorous comparative experiments.

Improving detection of hard-to-detect vulnerability types

As identified in Section 6.3, MDFVD, like other static analysis models, struggles with vulnerabilities that require reasoning about dynamic value properties (e.g., CWE-190 Integer Overflow) or complex external interactions (e.g., CWE-78 OS Command Injection). To address these limitations, we will pursue: (1) Integration of Lightweight Value Analysis, enhancing the ComCPG representation with static value range analysis or taint tracking labels to provide semantic hints for value-sensitive vulnerabilities; (2) Hybrid Modeling, combining GNN-based structural learning with specialized modules (e.g., symbolic execution or learned value predictors) for arithmetic-sensitive or interaction-heavy code regions; and (3) Focused Learning on Rare Types, employing techniques like cost-sensitive learning or targeted data augmentation for underperforming CWE categories to improve model sensitivity.

Enhancing generalization and scalability

We will extend MDFVD to support multi-language detection (e.g., Java, Python) by adapting intermediate code parsing modules for language-specific IR formats and exploring cross-language frameworks via multilingual pretraining models. Additionally, the scalability optimizations for ComCPG (incremental update, edge pruning) presented in this work will be further refined and evaluated on even larger industrial codebases, potentially incorporating distributed graph processing techniques.

These directions aim to transform MDFVD from a powerful detector for structural vulnerabilities into a more comprehensive, robust, and practical vulnerability analysis framework.

8 Conclusion

We propose a novel vulnerability detection model, MDFVD. For the extraction of local node features, MDFVD proposes MFES, which combines ABiGRU as a feature fusion network. MFES and ABiGRU can extract the local syntactic attributes and semantic features embedded in each statement from Sub-AST, PDG-Context, and ComCPG, and convert them into corresponding vector representations to serve as the local semantic information within the code statements. Moreover, through AMF-RGCN, the global feature information of the entire code segment can be captured, so as to more comprehensively extract vulnerability features and enhance the ultimate ability to judge vulnerabilities. In addition, ComCPG is a novel graph representation proposed for semantic feature extraction of source code, which incorporates richer syntactic structures and enhances contextual relevance. Our experimental results show that MDFVD has significantly improved vulnerability detection performance compared with existing methods.
